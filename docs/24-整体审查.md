## 2. 修掉的三个缺陷

### 2.1 `KB_TOP_K` 被并进了注释行（配置静默失效）

```python
# config.py:94（修复前）
KB_DIR = os.path.join(BASE_DIR, "data", "kb")   # 放入 .md/.txt 即自动入库    KB_TOP_K = int(os.environ.get("KB_TOP_K", "4"))
```

`KB_TOP_K` 整行被前一行注释吃掉，类属性根本没定义。调用侧写的是
`current_app.config.get("KB_TOP_K", 4)`，于是：

- 程序照常工作（默认值 4 兜着），**看不出任何异常**；
- 但 `KB_TOP_K=6 python run.py` 改了环境变量**不会生效**——配置项成了摆设。

这类错误不会报错、不会有日志，只有"改了配置没反应"时才会被怀疑到，
而那时候人通常先怀疑自己。**已拆成两行**，并在注释里写明这个坑。

### 2.2 越权办结返回 HTTP 200（这条最值得记）

```python
# app/api/tasks.py:209（修复前）
return fail("只能完成派给本角色的任务，或由街道关闭", code=403)
#    ↑ fail() 只构造 body，不设状态码；Flask 用默认 200 返回
```

全站错误返回的写法是 `return fail(msg), 4xx`，唯独这一处漏了状态码。
实测（物业账号去办结社区任务）：

```
HTTP: 200 | body: {"code": 403, "msg": "只能完成派给本角色的任务，或由街道关闭"}
```

后果不是"多一层解析"这么轻：

- 任何按 HTTP 状态码做的统计、监控、巡检，都会把**拒绝**算成**放行**；
- 上一轮线上核验脚本正是踩在这里——它按状态码判断，于是把"三次越权全被拒"
  读成了"越权全部通过"，进而让我误以为隔离失效；
- 顺着这个错误结论会去做错误的修复，比 bug 本身更危险。

已改为 `return fail(..., code=403), 403`，两者一致。

### 2.3 知识库增删不留痕

`kb.create_doc` / `kb.delete_doc` 直接写库/删库，**没有任何审计记录**。
知识库是系统回答居民政策问题的唯一依据：删掉《高龄津贴申领与年审指南》，
之后所有相关咨询都会变成"查无依据"——影响面比下一架一条公告还大，
而公告有 `publish/offline` 审计，撤销还有置顶额度提示。

更矛盾的是：**导出 Excel 都要留痕**（`views._log_export`），删掉政策依据却不用。
已补 `_audit("create_doc"/"delete_doc", ...)`，记文档标题、类别、字数/ID。

## 3. 发现但没改的（分级）

### 3.1 公告列表硬截断（中）
`api/notices.py`：`.limit(200).all()`，**无分页、无 `truncated` 提示**。
公告累积超过 200 条后，列表会静默少几条，且卡片数字（走 `base.count()`）
与列表对不上——正是本项目反复强调的那类"数字静默出错"。
改法：照 `orders` 的样子补 `page/size/matched/pages`，模板加分页条。

### 3.2 `/api/reports` 取 30 条无总数（低）
`.limit(30)` 且不返回 `matched`。报表一期一行，30 期后才会触发；
但一旦触发就是"最早的几期报表在页面上消失"。改法与 3.1 同。

### 3.3 三个接口仍返裸数组（低）
`/api/reports`、`/api/kb/docs`、`/api/admin/users`。
前端已适配、测试也锁了当前形状，所以不是 bug，只是与"列表一律
`{items,counts}`"的约定不一致——**同一个项目里两套形状，读代码的人要记两遍**。

### 3.4 前端没有网络异常兜底（中，可用性）
`base.html` 的全局 `fetch` 包装只处理 **401/403**，不处理：
- `fetch` 直接 reject（断网、代理挂、容器重启）；
- HTTP 500（后端 `_on_error` 会回 `{code:500}`，但页面多数直接 `j.data||{}`）。

结果：11 个页面里没有一个 `catch`（除首页），失败时表现为**空表格**或
永远停在"加载中…"，既不报错也不提示。这类问题在演示现场最致命——
观众看到的是"这个功能没做好"，而实际只是接口抖了一下。
建议加一个 `window.api(path)` 统一包装：失败时在页面顶部插一条
"加载失败 · 重试"，把 `catch` 从 11 个页面收拢到一处。

### 3.5 匿名 `/api/health` 多给了两项（低）
约定是"匿名只给存活状态"，实际还返回了 `llm.model`（`qwen3:8b`）与 `uptime_s`。
模型名等于把技术栈告诉扫描器。改动是一条 `if not user: data.pop(...)`。

### 3.6 两处未转义的 `detail`（低）
`system.html:110/160` 把 `pr.detail`（探活失败的异常文本）直接插进 `innerHTML`。
要利用得先控制上游隧道返回体，实际风险很低；但它在本项目里是**唯一的例外**——
其余 46 处都包了 `esc()`，留一个缺口会让"整站已转义"这个结论不成立。顺手 `esc()` 即可。

### 3.7 README 首屏断言与线上部署口径冲突（中，答辩相关）
README 第 8 行："全程本地大模型推理，**无任何外网调用**——这是本系统的硬约束"，
而 F18 又写"线上经隧道回本机 GPU"。两句都真，但放在一起会被追问：
隧道走 Cloudflare，请求确实出网了。
建议改成："推理只发生在本地 GPU；**内网部署时不出网**；线上演示为跨过云主机的
GPU 缺口额外加了加密隧道，此时请求经隧道回本机，模型侧仍不出网。"

### 3.8 测试套件共用一个源库快照（工程）
12 套 `smoke_*` 都以 `data/community.db` 为源拷一份独立库。问题在于**源库是活的**：
开发服务器在跑、或另一套正在写时，拷出来的可能是不一致快照（WAL 里的事务没合并），
表现为套件**秒退、输出为空**（这也是"批量跑不可信"的真实根因，
不是端口冲突——绝大多数套件用 `test_client`，根本不占端口）。
建议改成从 `data/community.db.seed`（发布用的冻结快照）拷，或用
`sqlite3.Connection.backup()` 取原子快照。

### 3.9 单社区假设（设计边界，论文要写清）
`FdeRecord` / `WorkItem` / `Ledger` / `Report` 都**没有主体维度**（org/community 列），
只有 `WorkOrder.property_co`、`Task.assignee_org`、`Notice.receiver_org` 三处隔离。
也就是说：多个社区共用一个实例时，社区 A 能读到社区 B 的事项与台账。
在"一个社区一套系统"的定位下这不构成缺陷，但**必须写成显式边界**——
否则"数据隔离"这句话在答辩时会被拆开问。

### 3.10 沙箱网关会改写防点击劫持响应头（低，平台行为，非本应用缺陷）
本应用发出的响应头是自洽的：

```
Content-Security-Policy: ... frame-ancestors 'none'; object-src 'none'
X-Frame-Options: DENY
```

但经 `community-agent.app.workbuddy.host` 网关后，实际到浏览器的是：

```
Content-Security-Policy: ... frame-ancestors 'none' *; object-src 'none'
X-Frame-Options: （被删除）
```

`frame-ancestors` 里 `'none'` 按 CSP 规范**必须是唯一源**，混入 `*` 后整条指令
被浏览器**直接忽略**（控制台原文：*"The keyword 'none' must be the only source
expression in the directive value, otherwise it is ignored"*）。也就是说沙箱域名上
这一层防护实际是关闭的；本机 `127.0.0.1` 与 ECS `47.108.235.113` 直连时正常生效。

**为什么不"修"**：网关加 `*` 与删 XFO 是为了让它自己的预览面板能 iframe 内嵌本应用。
若在前端加 frame-busting（`if (top !== self) top.location = self.location`）会把平台
预览一起打掉，而且 `sandbox` 属性可绕过，收益为负。结论记在这里，答辩时按
"平台托管层的行为，自建部署下防护完整"说明即可。

### 4.2 逐角色功能探测（本地实例，只读）

管理员 / 社区 / 物业 / 街道 四个账号 × 11 个页面 × 19 个接口 = 120 次请求：

- 所有页面 200，无 Traceback；
- 所有接口返回 `{code,msg,data}`，无 HTML 冒充 JSON；
- 越权一律 403（页面 302→登录、接口 403 JSON）——权限矩阵与 `ROLE_PERMS` 一致；
- 匿名访问 `/api/tasks` → 401，`/api/nope` → `{code:404}` JSON。

### 4.3 结构 / 契约静态核对

  `/dbwrite`（`APP_TEST=1` 才注册）、8 条居民端公开接口（各自做手机号+查询码/会话归属校验）。
  **无遗漏**。

## 5. 一句话结论

系统整体是**自洽且可演示**的：权限、隔离、留痕、降级四条主线没有断裂，
**25 套 1283 项断言**（24 套 smoke 1275 + 数据自洽 8）逐套实跑通过。这一轮查出的三个缺陷都属于"不报错但错了"的类型——
配置项被注释吃掉、状态码与响应体不一致、删除依据不留痕——
正好也说明这个项目最需要防的不是崩溃，而是**静默**。

优先级建议：3.4（前端异常兜底，影响演示观感）＞ 3.1（公告截断）＞
3.7（README 口径，答辩前必须改）＞ 3.8（测试源库）＞ 其余。
