## 安全 / 脱敏
- **脱敏正则顺序：身份证(18)在手机号(11)之前**，都加 `(?<!\d)...(?!\d)`；否则身份证中段被手机号先命中
- 审计摘要 `_audit()` **先脱敏再截断**；脱敏后落库（`search_text` 是 content 副本，不脱敏等于多存一份明文）
- 不用 X-Forwarded-For/remote_addr 做安全决策（代理池+可伪造），限流按账号/手机号
- SECRET_KEY 不在 config 类属性求值（导入即定死），在 `create_app` 裁决：env→`.secret_key`→dev 默认，prod 不回落公开串
- 居民端按 id 直取的详情页必须自判 `status`+`scope`；有 `visible_query()` 就别手写 `filter_by`
- 公开入口参数、测试断言要构造"缺字段/变化维度"，短路求值会掩盖未初始化变量
- **存储型 XSS 唯一防线是输出转义**：全站 41 处 `innerHTML` 拼接口数据，`base.html` 提供全局 `window.esc()`，7 页逐 sink 包裹；参数**不进属性**（`onclick="f('${title}')"` 会被引号打断，改传 id 查）
- **公告 scope 口径唯一**：`app/notice/ingest.py:staff_query(role)`/`can_view(n,role)`——社区/街道/admin 全放行，物业只 `published` 且 `scope∈{all,property}`。列表/counts/详情/导出四处都必须用
- `/api/health` 匿名只给存活状态（status/db.ok/llm.available），通道地址/pid/统计/db 报错只给登录者
- 居民 6 位查询码：连错 5 次锁 30 分钟，计数落 **audit_log**（`agent=portal, action=query_fail`，键 `portal:sha256(phone)[:16]`）；内存计数会被重启洗掉，打码手机号当键会撞号互锁
- 限流统一 `app/ratelimit.py:allow(key,limit,window)`（进程内滑动窗口，单进程前提）；注册按 IP 5 次/小时
- 响应头在 `app/fast.py:_secure_headers`；CSP `script-src` 仍留 `unsafe-inline`（11 页内联脚本），靠转义兜底
- **Cookie `Secure` 加不到 `after_request`**（会话存其后，此刻无 Set-Cookie）→ 包 WSGI `_HardenedWSGI`，按 `X-Forwarded-Proto`/`wsgi.url_scheme` 判 https；写死 True 本机 http 登不上
- **`Server` 头应用层改不掉**（Werkzeug 事后追加）→ `run.py` 换 `request_handler.server_version`
- 导出（docx/xlsx）**必须留痕**：`views._log_export()` 写 `agent=export` 审计；文件下载后脱离系统，事后只能靠这条追人
- **知识库增删也要留痕**（`api/kb.py:_audit`）：删一份政策文件 = 之后所有相关咨询"查无依据"，影响面大于下架一条公告，而 `created_by` 只记创建者、删除本身无痕

## 仲裁与证据链（2026-10-26）

- **"驳回"必须真的把状态改回去**：只在工单上记一句"已驳回"而不动 `status`，物业那边就没有重办入口，业务上等于什么也没发生。`reject` 是 `done → doing` 的**状态迁移**，不是标记位
- **`uphold` 是 `done → done`**：`from == to` 在这里合法（判定一次但状态不变），但起始状态要写死 `done`，否则会被误用到 `doing` 的单上变成"维持一个还没办完的结果"
- **`status` 与 `confirm_status` 是两条独立的线**，不能因为 `done` 就把 `disputed` 洗掉。同理，居委会"维持办结"之后居民状态**仍是 disputed**——替他改成"已解决"就是伪造居民意愿
- **裁决依据必须卡字数**（≥8 字）：不卡的话，"已协调处理""沟通完成"会成为标准答案，既说服不了居民，街道复核时也无法自证
- **回避原则要做双保险**：权限点不给物业（配置层）+ `can_judge()` 硬判角色（代码层）。只靠配置，管理员一次误勾就把制度破了
- **哈希链的能力边界别说过头**：能证明"没被改过"，不能证明"内容是真的"，也防不住拿到 sqlite 后重算全链。对外说"可验证未被篡改"，**不说"不可篡改"，不说"区块链"**
- **锚点只钉链头**：改链头并重算 → `anchor_mismatch`；改中间某条并重算 → 锚点不触发，靠下一条 `prev_hash` 对不上暴露成 `prev_mismatch`。四种篡改都要写进回归，不能只测最好测的那种
- **校验顺序必须是"锚点先、链内后"**：反过来的话，"改链头并重算"会先在下一条报 `prev_mismatch`，看着像"记录被删了"，实际是"内容被改了"——诊断错方向比不报还费时间
- **链上 `payload` 必须存脱敏快照**：为了"举证清楚"把原文塞进去，等于在 `evidence_chain` 里复制一份含手机号的明文，绕过 security Agent 和 field_security
- **附件按文件头判类型，不认扩展名**：`.php` 改名成 `.jpg` 一样能过扩展名检查。落盘用随机名——原名常是「3栋201身份证.jpg」，目录一泄漏等于把门牌和证件类型一起送出
- **`MAX_CONTENT_LENGTH` 必须设**：Flask 默认不限，居民端是公网匿名入口，一个 500MB 的 POST 就能吃干 2C2G 内存（Flask 会先把整个 body 读进内存再交给视图）
- **证据目录不能放 `app/static/`**：那等于把居民照片变成可直接访问的静态资源

## 统计 / 数据一致性
- **统计一律服务端 count，且与明细同源**（共用 `_scoped()`/`todo_filter()`）；禁用 `len(rows)` 与 `list.filter().length`（列表有 limit，数的是"这一屏"，/api/tasks 曾 133 条报 100 条）
- **筛选必须叠加条件**：写 `xxx_filter(base)` 而不是 `xxx_query()`（换整条查询会丢角色可见范围和 status）；**筛选只改 `matched` 不改 `total`**
- **卡片数字必须与它指向的列表同源**（否则"卡片 4 条、点进去 1 条"）
- **布尔列别 `func.sum()`**（Boolean 处理器把 23 归一成 True，`int()` 得 1）；用 `filter(X.is_(True)).count()`。常查布尔事实落真实列（`Ledger.reused`）
- **聚合别套聚合**：`db.session.query(func.count(X)).join(...).count()` 的外层 `.count()` 数的是"内层那条 SQL 返回几行"，内层无 `GROUP BY` ⇒ 永远 1 行 ⇒ 结果恒为 `1`（无记录时 `0`）。首页"敏感字段管控"实为 43、线上显示 1，就是这么来的。要么 `Model.query.join(...).filter(...).count()`，要么 `.scalar()`
- **断言不许照抄实现**：上面那个 bug 活过了两套回归，因为测试的"期望值"把实现那行表达式**原样抄了一遍**，两边同为 1。期望值必须走独立路径（裸 SQL / 手算常量），并加一条夹具自检（如"样本 >1 条"，否则对"恒返回 1"的实现也成立）
- 报表必须按 period 过滤（闭开区间 created_at）；**导出件只读 `data_json` 快照，绝不重查库**
- **报表一期一份 + 能回滚**（`app/report/revisions.py`）：`(period,line)` 唯一索引 + `Report.version`，重生成=覆盖升版；被替掉的整份存 `report_revision`（只追加），**覆盖前必须先 `archive()`**（顺序反了旧内容物理消失且不报错）；回滚=用旧内容生成新一版（`rollback_from` 记来源），回滚前也先归档；回滚挂 `report.generate`（街道只看不能改）；老库重复用 `scripts/_dedupe_reports.py --apply`
- 审计日志 `(created_at,id)` **游标分页**（offset 在只追加表会重复+漏读）；游标必须带 id（同秒多条会漏），坏游标退首屏；索引 `ix_audit_created_id`
- **重复发布不改写 `published_at`**（发稿时间是证据，误触把老文件顶到居民端最前）；只回提示不写库
- 接口契约：`/api/*` 的 404/405 统一回 `{code,msg,data}`（回 HTML 会让 `res.json()` 崩）；写请求按 `Sec-Fetch-Site: cross-site` 拦（不比 Origin/Host，托管网关会改写 Host）
- **错误返回必须带 HTTP 状态码**：`fail()` 只构造 body，`return fail(msg, code=403)` 会被 Flask 用 200 发出去 ⇒ 按状态码做的监控/巡检把**拒绝**算成**放行**（线上核验曾因此误判"越权全通过"）。全站写法是 `return fail(...), 4xx`，改完记得两边一致
- **配置项可能被注释吃掉**：`config.py` 一行 `# 注释    KEY = int(...)` 会让整个配置项消失，而 `.get(KEY, 默认值)` 兜着 ⇒ 改环境变量不生效且不报错。查法：AST 取 Config 类属性 vs 全仓 `config.get("X")` 比对（`KB_TOP_K` 就这么丢的）
- 分页参数非正值视作"没填"回默认（`max(1,...)` 会把 `size=0` 变成"只回 1 条"）
- 报表明细随报表冻结（`item_rows` 前 300 + truncated），`/api/reports` 详情剔除（EXPORT_ONLY）
- 工单 SLA 按知识库分级：紧急 4h/较急 24h/一般 72h（`dispatch.classify_sla`，未命中 72h）
- **置顶=排序不是状态**：`pinned` 与 `status` 解耦，须同时维护 `pinned_at`；`MAX_PINNED=3` 满额明确拒绝；未发布置顶件居民端不可见
- **居民端与内部列表排序同键**（曾一端按 `published_at`，两条置顶件顺序相反）；`pinned_at` 回填要**每次启动幂等执行**（`if col in added` 永远命中不了后产生的行）
- **居民单状态**：台账归档 `filed` 必须算办结（民政/综治线只写台账不产生工单，`all(s==done)` 会让它们永远停在「已受理」）
- **首页看板不许写死数字**（`GET /api/fde/dashboard`）：柱状图/折线/工时/今日任务原来全是常量，**录十条新事项图表一动不动**。x 轴只认 `parser.LINES`（曾有"城管"，库里根本没有）；一条事项可派多线 ⇒ 柱状图合计 ≥ 事项数，hint 要写明；趋势只画"本周一~今天"（画到周日，末端 0 像断崖）；今日无录入回退最近 6 条 + 标题改"最近录入"，不粉饰成 0；状态分布按今日**全部**事项算，不是屏上 8 行；**提交成功后前端要主动 `loadDash()`**，否则"真数据+不刷新"和假数据观感一样。回归 `smoke_dashboard.py` 61 项（每根柱子/每天/每个卡片都对一条 SQL）

## 并发
- **模型/外部 HTTP 绝不能放数据库事务内**：`flush()` 不等 commit，写锁仍持有 → 先 commit 落原文再调模型
- SQLite 必须 WAL + busy_timeout（`app/db_tuning.py` 自动挂），否则混合吞吐只有 1/2.65
- `LLM_MAX_CONCURRENCY=1` 是 8GB 卡物理上限（显存峰值 7566/8188MB）
- 压测/长稳 `--spawn` 自起实例 + 独立库；客户端 `Connection: close` + Barrier 预登录；每档至少 2 批

## 模型调用韧性（最凶的坑）
- **僵死槽位**：`requests.timeout` 不覆盖 DNS/半开连接 → 一次卡住让 `inflight` 永久=1，并发上限=1 ⇒ 全站排队降级，现象"模型全挂重启就好"。`LLMGate.reclaim_stale()` 按 `max_hold=timeout+30s` 回收，健康检查顺手调用；迟到交还靠 token 防 inflight 负值
- **失败必须归类** `kind`=connect/timeout/http_5xx/http_401/bad_response/queue；只重试前四类
- **探活超时要盖住 TLS 握手**：远程 25s、本机 3s（6s 会长期假报降级；**误报比不报更伤人**）；`probe()` 必须带 `error`+`ms`
- 托管平台前置网关 60s 硬掐

## 模型通道（线上真跑模型）
- 云服务免密钥 LLM 只能浏览器直连 → **隧道回本机 GPU**：云 Flask → cloudflared → `scripts/llm_gateway.py`(11435) → Ollama(11434)
- 配置优先级：`LLM_BASE_URL`/`LLM_TOKEN` env > 项目根 `llm.json`（源 `llm.publish.json`，**线上无 env 注入，只能靠它**）> config 默认。必须带 `keep_alive:"30m"`（默认 5 分钟卸载 4.7GB 权重）
- 本机 `127.0.0.1` 必须 `trust_env=False`（否则代理 404 静默降级）；远程 `trust_env=True`；远程 timeout ≥90s
- **平台变量别猜语义**：`SPACE_PROXY_ENDPOINT`/`X_IDE_AUTH_PROXY` 不是 HTTP 代理，塞 `proxies=` 反而弄坏直连；只认 `LLM_PROXY`/`llm.json:proxy`

- **换隧道后忘了推服务器 = 静默降级**（2026-10-23 补的缺口）：`ecs_deploy_code.py` 的 `KEEP_REMOTE` 保护 `C:\app\llm.json`，代码更新不会顺带换地址；旧地址失效后接口全 200、业务不报错，只有拆解质量退回规则桩 + 状态灯变红。`ecs_push_llm.py` 三条铁律：**不通就不推**（先从本机打隧道 `/api/tags` 拿到模型列表）、**只建两个连接**（scp 到 `_llm_new.json` 再由 ASCII+CRLF 的 .bat 备份→替换，半包不会写成半个 JSON）、**不重启应用**（`channel.py` 按 mtime 缓存，换文件即生效）
- **模型通道 ≠ 数据同步**：业务数据在服务器自己的 `data\community.db`，服务器就是数据源，两条线互不相干；别把"线上要能跑模型"理解成"两边数据要互通"（会引出 Tailscale/ngrok 转发写本机那一类方案，把可用性押在本机开机上）
- **起隧道三个必踩的坑（已在脚本修掉，别退回）**：
  1. 必须 `--protocol http2`。默认 QUIC(UDP) 本机 ESTABLISHED 但 Cloudflare 不回 "Tunnel created"，域名只给 error 页（路由没注册）
  2. 必须清代理变量（`child_env()`）。带 `HTTPS_PROXY` 去申请隧道一律超时（实测 000/10.5s vs 200/4.1s）
  3. 域名只能从 metrics `/quicktunnel` 读，不要解析 stdout（块缓冲 + **失败信息里也带 trycloudflare 域名**，旧正则把失败当成功 → 配置写成 API 域名 → 全站降级且不报错）。要求含短横线+排除 api，**探活通过才写配置**
- 隧道地址每次重建都变，TLS 握手 0.6~19s；观测 `/api/health`、`POST /api/health/llm-test`（admin 真跑）、`/system`

- **`audit_all.py` 的三处口径都先错后改**，改的方向一致：让规则自己判定，别把判断推给人。

  - 权限覆盖用 **AST** 看 `decorator_list`，不能正则看"上方两行"——`@perm_required` 写在 `@bp.get` **下面**，正则会报 81 个假裸接口；再补"函数体内 `current_user()`/`APP_TEST` 也算守卫"（`/api/admin/me`、`/api/health/dbwrite` 就是这种写法）
  - 模板转义按**字段语义**判：`${o.id}` 永远安全、`${l.feedback}` 必须 `esc()`。上一版"非 esc 即存疑"留 65 处噪声，现在是 esc52 / 数字枚举25 / 三元字面量8 / 标识符26 / **真风险 0**
  - **三元字面量白名单**：`(S.q || S.line) ? '没有…' : '暂无…'` 里 `S.q` 只参与条件判断，输出是固定中文。判成风险要人复核两遍——这类噪声正是报告被放弃的原因
  - **每加一条规则都要验证它能红**：塞一个 `innerHTML = \`<b>${l.feedback}</b>\`` 的临时模板，D 组必须 FAIL、退出码 1，且同文件的 `${o.id}` 不许报。恒绿的检查比没有检查更危险
- **备份不能复制 `.db`**：WAL 未 checkpoint 的事务会丢，得到"能打开但少几条"的坏备份。必须 `sqlite3.backup()`；每份备份过三关（`integrity_check` + 七表行数逐表相等 + 独立连接能查），不过就删
- **备份行数校验里有个镜像陷阱**：表名写错取数返回 -1，源库 -1、备份 -1 就"相等"通过 ⇒ 七项里一项从没检查。必须单独判 `-1` 并报错。**表名以 `sqlite_master` 实查为准**（`fde_record` 不是 `field_report`）
- `--restore` **只生成 `restored-<ts>.db`，绝不覆盖现网库**：运行中句柄被占用，替换会失败或写坏，连接池还指着旧 inode
- **改密脚本默认只预演**（`rotate_password.py`）：直接改会把人锁在门外。只走 `POST /api/admin/users/<uid>/password`（不直接改库，否则绕过审计与哈希）；改前确认旧口令可登、改后立刻验证新口令可登且旧口令失效。`--apply` 在**副本库+5010 独立端口**实测过
- **pre-commit 只跑 A/D 两组**（实测 0.5s）：跑全量会让人开始用 `--no-verify`，钩子随即形同虚设。启用 `git config core.hooksPath scripts/git_hooks`
- `audit_all.py` 的 F2 是**唯一有写副作用的只读项**：验默认口令必然写登录审计（成功/失败各一条），已在输出口径里写明

## 公文与周报（P0，2026-10-26）
- **发文与公告共用 `notice` 表，公告口径必须排掉 `direction='out'`**：一份"申请增补消防设施的请示"会出现在通知公告列表里，社区点一下"确认发布"就推到居民端——请示里写着经费数额和未决事项，这不是显示错，是泄密。修在 `app/notice/ingest.py:_exclude_docs()`，`staff_query` / `visible_query` / `can_view` / `todo_filter` 四处都要过它。**用 `or_(is_(None), != 'out')` 而不是裸 `!=`**：SQL 里 `NULL != 'out'` 是 NULL，会把老公告整批筛没
- **Jinja 里 `data.items` 会命中 `dict.items` 方法**，不是那个键：`{% for k, v in data.items %}` 报 `'builtin_function_or_method' has no attribute ...`。字典的键名撞上内置方法（items/keys/values/get）一律用下标 `data['items']`
- **周报数字与明细必须同源**：`collect()` 一次查询同时产出 `counts` 与 `items`（明细 id），页面点开逐条核。写成两次查询迟早对不上——`docs/14` 已经栽过一次
- **模型调用不能夹在事务里**：生成流程是"取数（只读）→ `rollback()` 结束事务 → 调模型润色 → 写库"。`rollback` 会让前面查到的 ORM 对象过期，所以草稿要在 rollback **之后**再查，否则拿到失效实例
- **用印时才取文号，不提前占号**：文号提前生成而最终没发，号段出现空洞，上级核对要解释。`make_doc_no` 只在 `seal`（或手动"取文号"）时调用；`doc_seq` 落库而不是从 `doc_no` 正则反解
- **社区没有定密权**：`secret_level` 里"秘密/机密"只用于继承上级来文，社区建文时标这两档直接 400。这一条如果不在代码里拦，做出来的功能在业务上是错的
- **改角色默认权限会打破写死数字的测试**：物业权限从 4 项加到 5 项（`doc.view`），`smoke_admin` 的"物业默认 4 项"立刻红。红得对——改断言时把**为什么变 5** 写进注释，别只改数字
- **幂等种子要能"续跑"**：`seed_docs.py` 中途 `push` 抛错会留下一份停在草稿、没有文号的半成品；再次运行若整份 skip，这份半成品就永远修不好。改成"按 `ALLOWED_FROM` 能推就继续推"

## ABAC 访问控制与导出水印（2026-10-26）
- **"拒"的规则必须排在"允许"之前**：`RULES` 里 R7 是"默认允许"。它一旦排到前面，后面所有限制规则永不生效，而接口照样 200、页面照样好看——这类 bug 不自曝，只能在回归里断言 `RULES[-1][0] == "R7"`
- **列表收窄与单条判定必须同源**：改造前"物业看不到别人的公告"有两份实现（`staff_query` 的 `scope.in_(["all", role])` 与 `can_view` 的 `(scope or "all") in ("all", role)`），空串处理已经差了；不一致的后果是"列表里有、点进去 404"，最难排查。现在两份都走 `policy.scope_query` / `policy.decide`
- **只有角色字符串时要套 `RoleShield`，且 `status` 必须给 `"active"`**：`staff_query(role)` 没有 User 对象，套壳时把 status 留空会命中 R1（账号状态），所有调用方都被判成"停用"，公告页整片变空。R1 的本意是拦真的停用账号，不是拦"我没传 status"
- **密级在库里是中文串，不能在 SQL 里比大小**：`"内部" > "公开"` 恰好在字节序上成立，但 `"内部·敏感"` 与 `"秘密"` 就乱了。列表侧必须翻译成 `IN (...)`，且翻译要用 `decide()` 同一个 `ROLE_SECRET_CEILING` 现算（`readable_secret_levels`），两处各写一份上下限就是下一条越权
- **认不出的密级要往上兜，不能往下兜**：新增一种标识（如"内部·敏感（含居民信息）"）而忘了登记，往下兜会把它当"公开"直接漏出去；`secret_num()` 兜底返回 5（机密）
- **空串密级 ≠ 公开**：老数据大多是空串，按 2（内部）处理。当公开等于让"忘了标"变成"对全网可见"
- **导出比查看严一档，但别用"密级上限"去卡**：给导出单独设更低上限的结果是用户截屏——反而失去水印与审计两条线索。正确做法是允许导，但强制水印 + 强制审计，让痕迹跟着文件走
- **水印必须写进文件字节里才算做了**：`apply_xlsx/apply_docx` 全都有 `except Exception: pass`，没校验字节时"函数被调用过"和"水印真在里面"看起来一样。回归里要解 zip 断言 `<headerFooter>`、`word/header` 真有水印文本，并断言 `headerFooter` 排在 `pageSetup` **之后**（CT_Worksheet 元素顺序是硬约束，反了 Excel 报"内容有问题"）
- **xlsx 只有页眉时屏幕上看不见**：Excel 的页眉只在打印视图渲染。所以要两道一起上：打印页眉（报送件可见）+ 数据区末行（屏幕可见）。只做前者，对方截个图发群里水印根本不在画面里
- **docx 水印只能动页眉，不能动页脚**：页脚已被 `_page_number()` 占用放 `- 1 -`，往第一个页脚段落塞水印会把页码盖掉——公文没页码是硬伤，且在屏幕上不明显，打印才发现
- **md 水印要写进 front matter**：md 第一行必须是 `---`，在正文顶上糊一行会让所有按 front matter 解析的导入脚本（`ingest.py` 自己就是）把它当标题，重新导入时标题全乱
- **页面水印要用 SVG 背景平铺，不能放一行居中大字**：单行居中截个角就没了。`pointer-events:none` 必须有（挡点击＝"页面坏了"），`user-select:none` 防顺手复制，`z-index:900` 要压在弹层之下
- **SVG 里的文本要先 XML 转义再 URL 编码**：姓名里出现 `&`、`<` 会让整条 CSS 非法而被浏览器**静默丢弃**——水印不显示且不报错。断言要看编码后的形态（`&amp;` → `%26amp%3B`），查裸的 `&amp;` 会误判
- **模板里不许写行内 `grid-template-columns`**：行内样式优先级让窄屏断点压不动它，375px 上横向溢出。用 `.frow` 这类 CSS 类（`smoke_mobile` 专门拦这条）
- **试算接口必须是只读的**：演示时会点几十次，每次都写审计会把真正的越权记录埋掉。取审计基线也要在**登录之后**——登录本身写一条审计，先取再登录会把这 1 条算到试算头上

## 流程监控 / 长尾预警 / 文本分析（`docs/33`，2026-10-26）
- **已办结的单必须算到 `done_at`，不是算到 `now`**：一开始 `age_hours()` 全用 `now`，18 张单里 **17 张被判"异常"**，等于没筛。9 月 20 日办完的单拿 10 月 26 日的 now 去减，得出"36 天未结"。**这个错不抛异常、不报错，只让告警排满早已办完的单**，使用者点开全是办完的，从此不看这个页面。改完降到 8 张。推论：凡是"从创建到现在的时长"，先问终点是什么时候
- **停留时长用相邻日志差，不用工单字段**：`order.assigned_at` 只记**最后一次**接单，转派一次就被覆盖，前面 40 天凭空消失——而这张单恰恰最该被看见。按 `(order_id, created_at, id)` 排序取相邻差，边（edge）才是流程挖掘的基本单位
- **分类问题必须在函数内部互斥，不能靠两条规则自己长眼**：`over_sla` 写成"超期 1 倍"和"超期 3 倍"两条 bool 规则，一张单同时显示「超期 3 倍以上、超期 1 倍以上」。改成判定函数返回命中说明（字符串），由函数内部给档位
- **分位数门槛不够时页面要写「样本不足」，不能渲染成横线 `—`**：横线被读成"这一格没数据"（没有这类工单），真实含义是"有，但不够算"，两者对决策的结论完全相反。`MIN_N_FOR_P90=5`、`MIN_N_FOR_MEDIAN=3`；n=1 的 P90 就是把那一条换个名字
- **异常检测用可解释规则，不用 Isolation Forest**：18 条样本喂进去，contamination 设低全部正常、设高全部异常。而且社区要的不是 0.87 分，是「这单跨 2 个单位、转 3 次、56 天没结，归你督办」——**规则写下来就是管理办法，模型给不出**
- **跨单位转派才是踢皮球**：只数 `transfer` 次数会把维修工请假、交接班误伤。用相邻转派的 `actor_org` 变化算 `cross_org`。41 张单里 `transfer≥3` 的 2 张，`cross_org` 也是 2 张
- **地点词、身份词不能当主题词**：「楼道」「单元门」「小区」说的是**在哪儿**，「老人」「业主」「孩子」说的是**谁**，主题词必须是问题本身或状态词。实测：词表里有「老人」时，"老人踩到积水滑倒"（漏水）、"老人拎垃圾走十分钟"（垃圾清运）、"老人被关在电梯里"（电梯运行）三条全被吸进「特殊群体」，**热点榜首变成"特殊群体 4 条"**，而真正要修的是水管、垃圾桶和电梯。改成只用状态词（独居/孤寡/空巢/高龄/低保/残疾/失能）后只剩 1 条，正是那条"独居老人两天没下楼"
- **宽泛字和常用词不能进词表**：卫生（在"卫生间"里）、臭（在"下水道"里）、邻居（在"邻居帮忙撬门"里）、单元门（在"1单元门口"里）。**宁可漏不要错**——漏了靠 `ngrams()` 补，错了没有任何机制能发现，而且使用者看到"漏水被归到垃圾清运"就再也不信这个页面
- **聚类纯度必须用严格版，宽松版是假象**：宽松版（取簇内最常见主题算占比）给 69.6%，但 2 条成员的簇里 1 条命中就给 50%，**随机分组也能刷到接近 50%**。严格版（簇内全体成员主题交集非空）给 39.1%，和人工核对一致
- **纯度随词表变，所以必须连词表版本一起报**：改词表去掉「老人」之后，**聚类算法一行没改**，同数据同阈值，纯度从 39.1% 掉到 30.4%（分子 9→7）。因为纯度拿人工词表当标准答案，标准答案变了分数就变。单独说"纯度 30%"没有意义
- **`max_df` 自动停用词滤不掉地点词**：0.5 / 0.35 / 0.25 三档纯度都是 39.1%、特征词表完全不变——噪声是**中频**地点词（"楼道""单元""物业说"各出现在四五条里），不是超高频。**"调参能解决"这个直觉在这里是错的**
- **短文本 2-gram 的字面相似度会骗人**：25 条诉求两两相似度中位数 **0.000**、max 0.505；"消防通道停车"与"下水道反水"相似度 0.343，仅因都含"物业说"。这个中位数比任何措辞都可信——一半以上的诉求连一个共同字串都没有
- **造数据的标记不能污染文本**：第一版用 `[演示]` 前缀拼进 `raw_text` 做判重，结果 `ngrams()` 榜首变成「演示」，演示时一眼看出是编的。改成按正文前 20 字（`SEED_HEAD`）判重与清理，**正文里不留任何痕迹**
- **造工单必须真建 `FdeRecord` → `WorkItem`**：`work_order.work_item_id` 有外键约束，传虚构 id 直接 `FOREIGN KEY constraint failed`
- **`_ticket_payload` 是个会写库的"读"函数**（自适应实现）：`check_integrity` 读旧值 → 调用它时被自适应更新 → 报不一致，所以脚本第一次跑会写库。造完数据要按 `itemstate.stage()` 回写 `ticket.status`
- **`line_summary` 用斜杠、`target_lines` 用逗号**：两种分隔符不能混用（`WorkItem.target_lines` 是 `,`，`ResidentTicket.line_summary` 是 `/`）。种子脚本两边塞同一个字符串，`check_integrity` 报"业务线与实际去向不一致"5 单
- **`with app.test_client()` 放在 `app_context` 内部会串 session**：`POST /login` 返回 302（看着成功）但下一次请求 401——test_client 复用已有 app context， Set-Cookie 没落进 client 自己的 cookie 存储。权限段必须拆到 `app_context` 之外
- **验证收窄别去查库**：查库等于用同一份实现验证自己。改成看接口返回的 `property_co` 字段
- **`can_judge` 缺防重复裁决会静默覆盖结论**：同一张单在同一轮被 `uphold` 两次，日志两条、verdict 被后者覆盖，事后复盘看到"判两次"却说不清哪次作数。判据用 `verdict_at >= confirm_at`（**不是"verdict 非空"**，reject 后 verdict 保留是历史结论）。代码修完后**库里那两条日志还在**，流程图上显示成「维持办结 → 维持办结」自环、停留 0.0 小时，演示时没人能解释这一格——所以要连数据一起清，并在回归里断言"裁决/确认类动作没有相邻重复"（注意 `转派 → 转派` 是**合法**的，那是踢皮球的证据，不能一起禁）
- **新页面不能绕过 ABAC**：`process`/`risk`/`textmine` 最初都直接 `WorkOrder.query.all()`，让物业看到全社区——工单页明明收窄了，新页面把收窄绕过去。统一走 `policy.scope_query` + `process.visible_ids()`

## Agent 协作与冲突消解（`docs/34`，2026-10-26）
- **"顺序调用几个 Agent"不是多 Agent**：原来 `Orchestrator` 是纯管道，把 `dispatch.run()` 换成普通函数调用系统行为一行都不变。要成立必须有两个 Agent 对**同一件事**各自表态 + 明确的消解规则 + 可追溯的消解记录。7 个 Agent 里只有 2 个调模型（parser/knowledge），这点要如实说
- **消解规则用"更严者胜"不用投票**：6 个 Agent 是规则实现，投票只反映谁词表更长；制度上两张 72h 的宽松结论不能压过一张"这户已经报过三次"。规则是**单向妥协**——合规只能加严不能放宽（`blackboard.TOPIC_RULE`）
- **没有分歧必须返回 `None`，不能记成"消解成功"**：把"意见一致"和"吵架后被裁定"显示成同一件事等于伪造协作，页面上每次都很顺畅、实际一次没冲突
- **定级要在建单之前，不能在建单后改 sla_hours**：先建单再改级会让流转链第一条 log 写着 72h 而工单字段是 4h，事后解释不清。决策权收归调度器，`DispatchAgent.run()` 接受 `payload["sla_level"]`，Agent 只执行不改结论
- **`resolve()` 不清空待议区会污染下一个业务项**：一条诉求拆出 3 项时，第 2 项的消解会把第 1 项留下的表态一起比大小，winner 停在第 1 轮。修法：`resolve()` 无论有没有分歧都把该议题移出 `self.claims`（表态仍留在 `steps`，页面时间线读那份）
- **判重键不稳定 = 功能静默失效**：复用 `fill.extract_room_key()` 时 `\d{3,4}室` 把"室"吃进去，"501" 与 "501室" 成了两个键，"重复报修"永远数成 0。而 subject 是模型重写的，同一户两次措辞必然不同，所以看不出来
- **真实诉求大多没有门号**：演示库 41 张单里只有 5 张能提出"栋+单元+门号"。电梯/楼道灯/门禁/垃圾桶都是公共设施，居民只会说"7栋3单元电梯异响"。只认三元组等于功能在真实数据上全线失效。修法：地址三级识别（`addr_parts`），精度按问题类别给——住宅类必须有门号（否则 501 和 502 合成一件），公共设施用"栋+单元"即可
- **判重必须"同址 + 同类"**：不加类别，"某栋某单元501漏水"会和"某栋某单元501电梯异响"算成同一件事，报修三次电梯的人被判定"漏水报了三次"
- **升档用 `dict.get(n, 0)` 会倒退**：`{1:1, 2:2}.get(3, 0)` = 0，**报修第 4 次反而不升级**且一路静默。改成 `min(n, CAP)` 单调不减。这种"次数越多越宽松"的错只有手工造到第 4 次才看得见
- **轨迹表不塞 `audit_log`**：审计是合规账本（250 字摘要、脱敏、留痕给监管），轨迹是内部复盘（谁的结论、依据、谁不同意）。读者、保留期、脱敏要求都不同，同表会让审计多一个泄露面
- **`limit=abc` 会 500**：`int(request.args.get(...))` 对非数字直接抛 ValueError。分页参数最常被手工改，统一走 `_int_arg()` 兜默认值
- **页面权限与接口角色白名单必须一致**：`/trace` 用 `fde.view`，接口 `TRACE_ROLES` 就必须正好是持有 `fde.view` 的那些角色。页面上进得去接口却 403（或反过来）会让用户看到空白页而日志记"放行"
- **一个 client 连续登录不同角色，只有第一个生效**：`/login` 第一句是 `if current_user(): redirect(...)`，已登录状态下再 POST 是空转。测试里切换角色**必须每个角色新建 client**（`smoke_insight` 的 `as_user()` 就是这个写法）
- **多个 prep 各自 `fresh()` 会互相拆台**：D 段造完用户、E 段又 drop_all，D 段所有请求回 401，看起来像权限判断失效。分段测试共用一次 `fresh()`

## 数据连通性（字段级，`scripts/audit_wiring.py`，2026-10-26）

## 前端「点了没反应」的四种真因（2026-11-03）
- **`.fail()` 不存在，写了等于把错误处理删掉**：`window.api()` 返回的是 `fetch().then()` 的原生 Promise，没有 jQuery 的 `.fail`。写成 `api(...).then(...).fail(...)` 会在**链式构造阶段**就抛 `TypeError`，后果有两层：① 错误提示永远不执行，失败时页面静默停在"加载中"；② **同一函数里它后面的语句全部不执行**。实测 `trace.html` 的 `loadStats()` 抛错导致后面的 `loadRuns()` 根本没被调用——"协作轨迹"页的运行列表永远是空的；`risk.html` 的 `load()` 抛错导致热点表永远"加载中…"。改法：`.catch()` + 显式判 `j.code !== 0`（`api()` 在业务失败时是 **resolve** 不是 reject，只 `.catch` 也会漏）。体检规则 D4 已固化
- **元素 id 改名后残留旧引用**：`getElementById('x')` 里的 x 不在本页 ⇒ `null.xxx` 空指针，表现同样是"按钮点了没反应"，且 console 只有一行红字，不点开根本看不见。体检规则 D5 已固化（扫描 `app/templates/**/*.html`，含 `portal/`）
- **按钮的失败条件写在数据里，页面却不知道**：公告"发布"要求标题与发文单位都不为空，而解析失败的来文 `issuer` 是空的 ⇒ 这条公告点"发布"**必然**被拒。详情页其实有"保存补全"表单（`PATCH /api/notices/<id>`，`post(url, body)` 有 body 就走 PATCH），但列表页只给了一个必然失败的按钮、也不告诉你去哪补。改法：列表里 `issuer` 为空时把"发布"换成"补发文单位"，`prompt` → PATCH → 自动发布。**判定口径**：按钮的每个失败分支，页面上必须有对应的补救入口，否则就是死按钮
- **接口失败被伪装成"没有数据"或者"旧数据"**：列表页写 `const j = await api(...)` 而不包 `try/catch`，两类失败各有各的骗法——通道层失败（502 / 超时）整段中断，`audit` 停在"加载中…"，`ledgers`/`kb`/`tasks` 则**继续显示上一次的数据**（用户当成最新的）；业务失败（HTTP 200 + `code!==0`）更隐蔽，`j.data` 为 null 就顺理成章走空态分支，显示"暂无记录""暂无台账，去首录台提交"。两种形态各造一次实测，四个页面全部中招。改法：`try/catch` + `j.code !== 0` 双判，失败时把原因写进表格本体并清空旧行（`base.html` 全局 `listFail()`），宁可空白也不留"看起来正常"的假象。体检规则 D6 已固化，判据**按行取窗口**：文件级"有一个 try 就算过"会被页面上别的 try 蒙混过去（`system.html` 的 153/179 行 try 与 `load()` 无关，照样裸着）

## 导出漏接、分页漂移与缺依赖（2026-11-03 整体复查）

这一轮查的是「静态看着都对、接口一跑就错」的三类问题，共同点是**本地全绿、线上/边界才炸**。

- **导出端点漏接 ABAC / 水印 / 审计**：报表导出与公文导出都有 `decide()` + `wm_text()` + `log_export()` 三件套，**底册导出却只挂了 `@perm_required("person.view")`**。`person.view` 管的是"能不能看列表"，而文件一旦下载就脱离了页面——不留痕意味着 300 个居民的姓名 / 证件掩码 / 门牌 / 残疾等级被谁在什么时候导走，事后查不到。最敏感的「人」反而比「报表」留痕更少。改法：`decide(u,"export","person",secret=2)` 由 R6 一处决定能不能导 / 要不要水印 / 要不要留痕；`apply_xlsx` 打双道水印（打印页眉 + 数据区末行）；`log_export` 只记表名与条数、不记姓名（轨迹本身也会被导出）。同时把原来是 `views.py` 私有函数的 `_log_export` 抽成 `app/exportlog.py`，三处共用一份——**同一个动作写两遍，就一定会漏一遍**。体检规则 C4 已固化（按 URL 含 `export` 定位端点，函数体内须同时出现 `decide(` / `wm_text(` / `log_export(`）
- **分页排序没有唯一键兜底**：`order_by(created_at.desc())` 单独用，而 `created_at` 会大量重复——`person` 表 300 行时间戳**全相同**（导入时统一打）、`ledger` 18 组重复（37 行）、`work_order` 3 组（6 行）。同值行的返回顺序由 SQLite 执行计划决定（走索引 vs 全表扫描不一样），一旦 `OFFSET` 分页跨在这些行上，同一条可能在两页都出现、或一条都不出现。**现在复现不出来**（小表走全表扫描、rowid 顺序恰好稳定），但那是实现细节不是保证：加索引、数据量变化、有 UPDATE 之后就会漂。改法：`order_by(..., id.desc())`，不改变已确定的顺序（`created_at` 仍优先），只让同值行有确定次序。实测台账 60 条翻 6 页 0 重复 0 遗漏、两次请求顺序完全一致
- **函数内 `import X` 让缺依赖只在触发时 500**：`openpyxl`（底册导出）、`numpy`（文本聚类）、`psutil`（健康页采样）都写成函数体内 import，而线上 `C:\Python313` 一个都没装（`requirements.txt` 从未声明）。本地 venv 碰巧装了，所以永远测不出来；用户一点导出就是"服务内部错误"。**上线前必须在服务器上逐个 `import` 探一次依赖**，不能只信 `pip install -r` 成功了。新增导出/解析优先复用自研 `app/xlsx.py` / `notice/export.py`(docx)，别另起炉灶引第三方库——这两个自研写入器存在的理由就是不让"能不能发布"押在第三方包上

**排查方法论**：这三类问题静态审查都看不出来。有效手段是①**全端点运行期探测**（4 角色 × 全部 GET 路由，只把 5xx 与非 JSON 当问题，4xx 是权限的正常结果）；②**数字对账**（接口说多少就回库数一遍）；③**在服务器上逐个 import 探依赖**。另一条同样重要：**先排除探测工具自己的噪声再下结论**——`[street] /` 报 30 秒超时，单独跑只有 43ms，真因是连续导航时某页的 `/api/health/llm` 探活吃掉了下一次 goto 的预算；`[admin] /health` 报 404 是因为 JSON 端点不经过 `base.html`、没有 `<link rel="icon">`，浏览器必然去要 `/favicon.ico`；非 admin 角色访问管理员页的 403 是权限设计生效。**这三条都是"看起来像 bug"，实际是探测脚本判据太宽**。

### 同一条"能不能看"的规则写在多处，每加一个端点就漏一次（2026-11-04）

公文 `direction=out`（本级发文）明确不进公告体系——`can_view()` 第一条就是 `if direction == "out": return False`，详情页也确实回"公告不存在"。**但这条规则只写在详情里**：

| 路径 | 修复前 | 修复后 |
|---|---|---|
| `GET /api/notices/<id>`（详情） | 拒绝 | 拒绝 |
| `GET /api/notices/<id>/draft`（取落地件草稿） | **200 + 完整正文** | 404 |
| `POST /api/notices/<id>/localize`（生成落地件） | 能创建 | 404 |
| `POST /api/notices/<id>/receive`（签收） | 只判 `receiver_org` | 404 |
| `PATCH /api/notices/<id>`（补全字段） | 返回正文 | 404 |
| `GET /notices/<id>/localize`（**页面**） | 渲染正文编辑器 | 404 |
| `GET /portal/notice/<id>`（**居民端**） | 只判 `status`/`scope`，**漏了 out** | 404 |
| `publish` / `take_offline`（ingest 内部） | 能改状态 | 拒绝 |

实测证据：社区账号对 out 公文（id 5/6/7）请求 `/draft`，返回 `code=0` 和 363 字节正文「根据幸福里社区居民委员会《关于申请增补 3 栋高层住宅消防设施的请示》…」。

修法：抽 `_load_visible(nid)`（取 + `can_view` + 统一 404 文案），所有按 id 取公告的业务端点共用；页面与居民端各自调 `can_view`，不再手写条件。居民端原来手写 `status != "published" or scope != "all"`，比列表侧 `visible_query` 少了 `_exclude_docs` 这一条——**列表与详情不同源，就会出现"列表里没有、拼 id 能打开"**。

体检规则 **C5** 固化：扫所有含 `db.session.get(Notice` 的函数，函数体内必须有 `_load_visible(` / `can_view(` / `direction` 之一。加规则时先验证能红（临时打断 `views.py:notice_localize` → 报出该函数），恢复后 0 处。

顺带修了体检自身的一个静默缺口：`F1 服务健康` 连不上时原来直接 `return`，F2/F3/F4 三项**不报也不跳过**，总数从 29 悄悄变成 26。改成显式 SKIP——「没查」和「查了没过」必须在报告里分得开。

| CSRF | 带不同 `Sec-Fetch-Site` 头 POST | `cross-site` → **403**；`same-origin` / `same-site` / 无头 → 放行；GET 不拦 |
| 时区 | 统计 `datetime.now()` vs `utcnow()`，比对库内最新时间戳 | 55 处全 `now()`、0 处 `utcnow()`，与本地时间一致 |

**这一轮的方法论收获**：静态审查只能证明"代码按我理解的方式写了"，证明不了"它在异常输入下不炸"。**边界模糊测试、空库场景、SQL 计数、真实浏览器渲染**这四种手段，各自能撞出静态审查看不见的一类问题。而每一条"发现"都要先排除探测工具自身的噪声——本轮就误报了三次（`undefined` 来自 JS 关键字、身份证中段被手机号正则命中、`/api/security/policy` 是我猜的路径）。

## 阿里云 ECS 评估（备选部署）
- `ecs.e-c1m1.large`：2 vCPU 共享 / 2GB / 3Mbps(≈384KB/s) / 40G，99 元
- 实测本项目 RSS 82MB、单页 gzip 4.5~8.4KB、渲染 3.5~4.2ms → 应用层绰绰有余；**跑不动 qwen3:8b**（4.7GB 权重+5~6GB 内存）→ 模型仍留 4060 走隧道
- 安全组默认只开 22；绑域名需 ICP 备案（IP:端口不用）；生产用 gunicorn；部署包 `F:\bise4-deploy\community-agent.tar.gz`，`workbench` CLI 需用户本人填 AK
- **代码更新 ≠ 数据同步**：`scripts/ecs_deploy_code.py` 只换 `app/`+`run.py`+`config.py`，`data/` 不动；数据方向由 `ecs_sync.py push/pull` 人工决定。两条路混用会互相打脸（push 覆盖服务器写入，见 docs/27 §5）
- **链路一次只让你连一次**：22 端口 TCP connect 约 50% 成功，同一终端里连发第二条连接基本必失败。脚本里"一个动作一次连接 + 失败重试"，服务器侧多步骤合并成一个 .bat 一次下发（分四次下发断在中间 = 代码换一半、服务停了）
- **Windows `.bat` 两条铁律**（踩了 4 次才通）：① 行尾必须 **CRLF**，只有 LF 时 `if...else` / `for...do(...)` 会被错解成 `2>&1 此时不应有`，而且**前面的行已经执行**（备份做了、替换没做）；② **不能有中文注释**，UTF-8 中文在 `rem` 行会被当命令报"'……' 不是内部或外部命令"。生成 .bat 一律 `ASCII + CRLF`
- **停服只杀 :80 上的 PID**（`netstat` 取 PID + `taskkill /pid`），别用 `taskkill /im python.exe`：`ca-sync` 每分钟也会起 python，正在 apply 快照时被杀会打断事务
- **本机 `.bat` 可以写中文，但插入的行也必须是 CRLF**（2026-10-26 写 ECS 模型启动 bat 时踩到）：本机 bat 走 GBK 控制台（`chcp 936` + `PYTHONIOENCODING=gbk:replace`），中文 REM 本身没问题；但用脚本"向已有文件插入"内容时若混进裸 LF，cmd 会把中文 REM 截成半行——现象是启动先报两行 `'肪车髌鹗?LOCALAPPDATA' 不是内部或外部命令`，**然后照常往下跑**，于是很容易忽略。生成后必须断言 `raw.count(b"\n") == raw.count(b"\r\n")`
- **`timeout /t N` 不能用来延时**：stdin 被重定向时它直接报"不支持输入重新定向"并退出，延时完全失效（循环里刷出一串错误）；另外 Git Bash 的 PATH 里 `/usr/bin/timeout` 会盖掉 Windows 的 `timeout.exe`，它不认 `/t` 参数。统一改用 `ping -n N+1 127.0.0.1 >nul`
- **从 Git Bash 调起的 cmd 里 `LOCALAPPDATA` 可能没导出**：`%LOCALAPPDATA%\Programs\Ollama\ollama.exe` 会拼成 `\Programs\Ollama\ollama.exe`，于是"明明装了 Ollama"却报未安装。开头兜底 `if not defined LOCALAPPDATA set "LOCALAPPDATA=%USERPROFILE%\AppData\Local"`（双击运行时本来就有，这行只防非常规启动）
- 服务器上守着不放的东西：`main.py`、`start_server.bat`（`set PORT=80`/`FLASK_ENV=prod`）、`llm.json`（隧道地址+令牌）、`.secret_key`、`data/`、`snapshot_apply.py`、`sync_once.bat`
- 服务真实启动方式：计划任务 `community-agent-run` → `start_server.bat` → `C:\Python313\python.exe C:\app\run.py`（`PORT=80`）。`community-agent` 是开机触发的那一份
- **`ecs_sync.scp(local, remote)` 只能上传**：第二个参数会被硬加 `user@host:` 前缀，想下载不能复用。下载直接拼 `subprocess.run(["scp","-i",KEY]+SSH_OPTS+["Administrator@IP:远端路径", 本地路径])`
- **scp 的远端路径必须用正斜杠**（2026-10-26 同步时踩到）：`C:\data-incoming\x.db` 会报 `No such file or directory`（反斜杠在 scp 的参数解析里被吃），换成 `C:/data-incoming/x.db` 立刻成功。同一个路径在 `ssh ... python -c` 里用反斜杠是没问题的，**只有 scp 不行**
- **判断"服务器有没有被人用过"不能用 `audit_log` 的时间**：登录就写审计，`max(created_at)` 永远等于"此刻"，看起来像刚有人在用。要看业务表（`work_order` / `task` 的 `max(created_at)`）。10-26 同步前服务器 work_order 停在 10-23 13:13、task 停在 10-23 14:00，据此才敢 push
