# 20 · 信息安全加固

> 目的：不问"有没有做安全"，而是**逐条打一遍**，把"文档里写了、代码里没有"的地方找出来。
> 体检脚本 `scripts/sec_probe.py`（27 项，只打印现状不预设结论），
> 断言版 `scripts/smoke_security_hard.py`（62 项，防复发）。

首轮体检 **27 项里 16 项不通过**，分布在 7 类。本文按"现象 → 根因 → 修法 → 验证"记。

## 1. 存储型 XSS：整站 41 处 `innerHTML` 在拼外部输入

### 现象

页面全用 `el.innerHTML = \`...\`` 渲染接口数据，这类写法一旦有字段没转义，就等于把
"用户填的内容"当 HTML 执行。实际可点亮的链路有三条：

| 注入源 | 落点 | 触发者 |
| --- | --- | --- |
| 自助注册的**真实姓名**（自由文本） | 审计日志 `actor` 列 → 审计页表格 | 任何打开审计页的管理员 |
| 居民提交的 **FDE 原文 / 反馈** | 台账列表 `subject` / `feedback` | 社区、街道 |
| 街道导入的**公文标题** | 知识库列表 `title`、检索命中 `title` / `snippet` | 任何有 `kb.view` 的账号 |

最严重的是第一条：注册是**公网匿名可写**的，攻击者把姓名填成
`<img src=x onerror="fetch('/api/admin/users')…">`，管理员一打开审计页就在自己的
会话里执行了它——会话 Cookie 是 HttpOnly，脚本读不到，但**同源 fetch 不受限**，
等于一条完整的越权链。

### 根因

只有 `orders.html` / `notices.html` / `tasks.html` 自带 `esc()` 并用它包了数据；
其余 7 个页面（`audit` / `ledgers` / `kb` / `reports` / `index` / `system` / `notice_localize`）
直接把 `${x}` 拼进模板串。esc 是页面局部函数，换个页面就得重新定义一次——所以"漏一处"
是常态，不是意外。

### 修法

1. `base.html` 里定义**全局** `window.esc()`（转义 `& < > " '` 五个字符），所有继承
   base 的页面直接可用，不必各自再写。
2. 逐个 sink 改：审计页 6 列、台账 6 列、知识库标题/分类/命中片段、报表摘要与版本说明、
   首页时间线（脱敏原文、业务项、知识库命中、工单推送对象）、系统页运维字段。
3. 顺手修了一个"拼 JS 字符串"的坑：知识库删除按钮原先把标题拼进 `onclick`
   （`delDoc(id,'标题')`），标题里带单引号就把这段 JS 弄坏。
   改成 `delDoc(id)`，标题在函数里按 id 从已加载列表取——**参数不进属性**，问题从源头消失。

### 验证

- `smoke_security_hard.py` 断言 6 个页面的关键 sink 都过 `esc()`（源码层守卫，
  改了模板就会红），并断言 `base.html` 提供全局 `esc` 且转义五个字符。
- 覆盖了"审计接口返回 JSON 而不是 HTML 页"这一层：XSS 的防线是**输出编码**，
  不是靠接口返回类型。

## 2. 公告发布范围 `scope` 形同虚设（越权读取 + 越权导出）

### 现象

`Notice.scope` 有 `all / community / property` 三档，语义是"这份件给谁看"。
但内部接口一律 `Notice.query`，**只有居民端用了 `visible_query()`**：

- 物业账号的列表里能列出 `scope=community` 的社区内部排班表；
- 按 id 直取能拿到正文（`body_md`）与解析备注；
- `/notices/<id>/export/docx` 能把这份内部件**导出成 37KB 的 docx**；
- 连 `status=pending` 的草稿也能读——"还没确认"的内容先流到了别的单位。

### 根因

口径只写在居民端一处，内部端三个入口（列表 / 详情页 / 导出）各写各的。
而且导出比"看"更严重：文件一旦下载就脱离系统，拦不住二次传播。

### 修法

在 `app/notice/ingest.py` 里定死一套内部口径，**列表、详情、页面、导出全部共用**：

```python
staff_query(role)   # 列表/计数用：物业 → status=published 且 scope∈{all, property}；
                    # 社区/街道/admin → 不过滤（发布方要确认草稿，监督方要看全区）
can_view(n, role)   # 单对象用，与上面同口径
```

配套两处细节：

- **计数与列表同源**（`counts` 也走 `staff_query`）。否则会出现"卡片写 1 条、
  点进去 0 条"，用户没法判断哪边是真的。
- 页面与导出各判一次，不复用"列表里有就等于能看"的假设——页面是最容易漏的一层。

### 验证

`smoke_security_hard.py` 该轮新增 15 项（现全量 62 项）：物业列表不含内部件/草稿、按 id 直取被拒、
页面 404、导出 404、面向自己的件仍能看能导；社区仍能读内部件与草稿（**不能修过头**）；
街道仍能读全部（监督口径）。原有 `smoke_notice_flow` 里那条
"物业也能导出"也跟着改口径：未发布件导不走，发布后能导。

## 3. `/api/health` 把部署形态白送给匿名访问者

### 现象

未登录 `GET /api/health` 返回：模型通道地址（线上就是隧道域名）、令牌是否配置、
进程 PID、线程名、调用统计、数据库引擎与**报错原文**。这些不是业务数据，
却是攻击面的地图：知道网关地址就能直接打那个端口，`db.error` 里常带表名与绝对路径。

### 修法

分两档：**匿名只给存活状态**（`status` / `db.ok` / `db.latency_ms` / `llm.available` /
`model`），登录后才给完整运维详情。

为什么不是"只给管理员"：模型通道抖动时，社区值班的人也要能自证"是模型降级了，
不是我操作错了"，卡在管理员那里会让排障变慢；而匿名者本来就不该看到这些。

连带影响：`soak_test.py`、`bench_concurrency.py` 的采样改走已登录会话；
`smoke_llm_channel` / `smoke_llm_resilience` 里"健康接口暴露通道类型"的断言
改成"匿名不暴露、登录后暴露"。

## 4. 居民端 6 位查询码：能枚举，只是慢

### 现象

`/api/portal/ticket` 只有"同号 20 次/分钟"的滑动窗口。10⁶ 个码 / 20 次每分钟 ≈ 35 天跑完，
但攻击者只盯一个手机号、每天跑满额度，一个月内仍有可观概率撞对；撞对一次的后果是
**读到别人家的姓名、门牌、报修内容**。

### 修法

连错 5 次锁 30 分钟，计数**落在审计表**而不是内存字典：

- 内存计数随重启清零，而"重启"恰好是部署更新、平台迁移时必然发生的事——
  攻击者等到那一刻就能洗掉计数，锁定等于没有。
- 审计里的键用 `sha256(手机号)[:16]` 而不是打码手机号：`138****8000` 只有 7 位有效
  信息，两个不同号码撞在一起会变成"别人的失败把我锁了"。
- 锁定按手机号隔离：一个号被锁不影响其它号（`smoke` 里专门断言）。

顺序也有讲究：**限流 → 格式校验 → 锁定检查 → 查库**。格式都不对的请求不写审计、
不占额度，否则一条乱码脚本就能把审计表写满。

## 5. 自助注册是公网可写入口，却没有限流

未登录 `POST /register` 连发 6 次，6 个待审核账号全部落库。真实后果不是"数据库变大"，
而是**管理员列表被刷屏、审核功能失效**；顺带"该账号已被占用"这句提示本身就是账号枚举工具。

修法：抽出 `app/ratelimit.py`（进程内滑动窗口，零依赖），注册按 IP 限 5 次/小时；
居民端的两处限额也改成复用同一实现——限流口径分散在各模块时，很容易出现
"同一入口 A 处限 20、B 处限 120，看起来都限了，实际按宽松的走"。

## 6. 安全响应头与 Cookie 标记

### 缺失项

5 个安全头全缺，且 `Server: Werkzeug/3.1.9 Python/3.13.14` 把"该查哪个 CVE"直接
告诉扫描器。

### 修法

`app/fast.py` 统一加：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、
`Referrer-Policy: same-origin`、`Permissions-Policy`、以及 CSP：

```
default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline';
script-src 'self' 'unsafe-inline'; connect-src 'self'; form-action 'self';
base-uri 'self'; frame-ancestors 'none'; object-src 'none'
```

CSP 里 `script-src` 仍留 `'unsafe-inline'`：11 个页面都是内联脚本，改 nonce 要动所有
`<script>`，而真正的防线是**输出转义**（第 1 节），CSP 在这里是第二层护栏。
`frame-ancestors` / `base-uri` / `object-src` 三项不影响内联脚本，直接收紧。

### 两个时序坑（都踩了才知道）

1. **Cookie 的 `Secure` 不能在 `after_request` 里加**：Flask 存会话是
   `process_response` 的最后一步，after_request 跑的时候响应头里还没有 `Set-Cookie`。
   实测打出来是空数组，改了半天没反应。最终在 **WSGI 层**包一层 `_HardenedWSGI`：
   按 `X-Forwarded-Proto` / `wsgi.url_scheme` 判断真实协议，是 https 才补 `; Secure`。
   写死 `True` 会让本机 http 调试直接登录不上（浏览器丢弃 Secure Cookie）。
2. **应用里写 `Server` 头是白改**：Werkzeug 开发服务器在应用返回之后**再追一条**自己的
   `Server`，响应里就是两条。改成在 `run.py` 里换 `request_handler` 的
   `server_version`（banner 归服务器层管），应用层只负责把重复的合并成一条。

## 7. 导出动作没有留痕

公文 docx、报表 xlsx 一按就下载，**审计里什么都没有**。页面浏览有日志，文件存到本地之后
再没有痕迹——事后追"这份内部件是谁拿走的"无从下手。

修法：`views._log_export()` 在导出前写一条 `agent=export` 的审计（记操作人、
文件名、报表期次与版本）。放 `build()` 之后，格式不支持导致的失败不记账；
写审计失败也不阻断下载（审计是附加证据，不是导出的前置条件）。

## 8. 明确没做 / 做不到的（边界）

| 项 | 现状与理由 |
| --- | --- |
| CSRF Token | 只靠 `Sec-Fetch-Site` + `SameSite=Lax`。现代浏览器两者都在，跨站写已被拦（回归里有 403 断言）；老旧客户端不发 `Sec-Fetch-*` 时退化成纯 SameSite，仍是浏览器级防护。要上双提交 Cookie 就得改所有表单与全部前端 `fetch`，收益边际 |
| CSP 去掉 `unsafe-inline` | 需要给 11 个页面的内联脚本加 nonce 并改造内联事件处理器（`onclick=` 遍布表格行），改动面大于收益；输出转义已经把"注入点"堵住 |
| 限流是单进程内存 | 多 worker 部署时每个进程各限一份 = 限额 × worker 数；重启清零。要真做只能上 Redis，与"零依赖、可整包搬移"冲突。现状是单进程跑，够用 |
| 依赖漏洞扫描 | 未接 `pip-audit` / Dependabot。发布件只有 Flask + SQLAlchemy + requests 三个直接依赖，且固定版本；接扫描需要联网拉漏洞库，沙箱里不保证可用 |
| 无 WAF / 无入侵检测 | 属部署层能力，不在应用范围内。托管平台有基础防护，但本项目不做承诺 |
| 多租户隔离 | 当前部署是"一个社区一个库"（`data/community.db`）。物业按 `property_co` 隔离已在查询层与写接口两侧做（`docs/04`），但没有"多社区同库"的隔离，也不打算做——那是产品形态变更，不是安全补丁 |
| 审计表会被失败尝试写入 | 查询码每错一次写一条；按手机号 20 次/分钟限流封顶，代价可控。要更省可以只记"第 5 次"，但会丢掉"错了几次"的证据 |
