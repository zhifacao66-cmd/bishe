## 3. 定稿文案

### 3.0 数字怎么放（先定规则）

简历不是评测报告。**一屏里塞三十个数字，读的人一个也记不住**，反而显得在堆料。
规则三条：

1. **结构性数字用汉字**：八个 Agent、一个编排器、五类角色、三条约束、十六并发。
   汉字读起来是"结构"，阿拉伯数字读起来是"指标"，混在一起才像报表。
2. **度量值只留三个能直接支撑结论的**：`59 → 24`、`97.7% / 99.0%`、`P95 55ms`。
   其余（消融的 +16.3/+23.5/+54.0、单条 1.5s、QPS 275、1,960 项）留在 `docs/03`、`docs/07` 备查，
   面试被追问时再报——**答得出来**比写在纸上更有用。
3. **规模合并成一句**：行数、接口数、测试套数缩成"约一万五千行、六十余个接口"，
   放在最后一条。带"约"和"余"，既给了量级，又不承担逐位对账的义务。

### 3.1 主版本（推荐，5 条）

> **社区"极简减负"智能体系统**（三方协同治理）｜ 独立开发 ｜ 本科毕业设计
> `Python` `Flask` `SQLAlchemy/SQLite` `Ollama qwen3:8b` `ECharts` `阿里云 ECS`

- **面向社区「居民—物业—居委会」三方协同，设计八个专职 Agent 加一个编排器的协作链路**（脱敏审查 → 业务拆解 → 派单/填报 → 督办/报表），一段口述自动落成工单与台账；端到端评测中手工录入由 59 次降至 24 次，漏派与误派均为零
- **把本地 8B 模型的自由文本收紧为结构化 JSON**：JSON Schema 约束解码加不合规整体重试；43 条标注集上业务项数量准确率 97.7%、类型 F1 99.0%、业务线去向全部命中，并以纯规则为基线做消融，量化每项工程手段的独立贡献
- **设计规则桩降级链路**：模型不可用时自动回落规则引擎，接口照常返回、页面不空白；规则路径同时作为消融基线
- **把制度约束写进代码而不是只写进制度文件**：五类角色功能点级授权，页面与 API 双守卫、越权逐条断言 403；关键设计是把**责任判定**而非满意度作为仲裁结论（物业责任退回重办 / 业主自用维持办结），并让争议当事方物业在**配置层拿不到、代码层再拒一次**（回避原则），裁决不写依据不予受理；在此之上再叠一层属性级保密——密级五档对角色可见上限，行级可见范围与单条判定同源，导出强制水印并留痕
- **独立完成系统实现与部署压测**：近两万行代码、八十余个接口；用阿里云 ECS 与 Cloudflare Tunnel 把推理回传本机 GPU，绕开服务器装不下 8B 模型的限制；为争议环节做哈希链存证，链头由居委会与街道各自锚定，改内容、删记录、连哈希一起重算三种篡改均可检出；全量回归逐套独立建库单跑全绿，十六并发下接口 P95 55ms

### 3.2 精简版（版面紧张时）

> **社区"极简减负"智能体系统**（独立开发 / Flask + Ollama + SQLite，三方协同治理）
> 八个 Agent 加一个编排器把口述转成工单与台账，录入动作由 59 次降到 24 次；用 JSON Schema 约束解码让本地 8B 模型稳定输出结构化 JSON，标注集上数量准确率 97.7%、类型 F1 99.0%；五类角色功能点级权限，并把仲裁做成"物业回避 + 依据必填"的闭环；再叠一层属性级保密（密级对角色上限、导出带水印）；争议环节哈希链存证；独立完成部署、回归与并发压测。

### 3.3 技术关键词行（供 HR 筛选）

`Python` `Flask（工厂 + 蓝图）` `SQLAlchemy` `SQLite（WAL）` `Jinja2` `多 Agent 编排` `结构化输出` `Prompt 工程` `Ollama/本地推理` `BM25 检索` `ECharts` `RBAC + ABAC 分层访问控制` `回避原则/裁决规则` `哈希链存证` `导出水印` `审计脱敏` `自动化回归` `Windows Server 运维`

## 7. 三个必被问到的问题

**Q：为什么用 8B 不用 API？**
政务数据不出内网是硬约束；且本地推理有降级兜底，模型挂了业务不挂。代价是吞吐被单卡锁死在 0.62 QPS，所以做了规则桩 + 异步化的取舍。

**Q：97.7% 是怎么算的？**
`scripts/eval_parser.py` 43 条标注、50 个期望业务项；「数量准确率」= 预测项数等于标注项数的样本占比。相对 baseline 的每一步提升都在 `docs/03` 的消融表里，同一批样本、同一条 prompt。

**Q：59.3% 怎么来的？**
24 条语料推到 35 张单据，人工要在纸/群里记一次再逐表填一遍，共 59 次；系统里一段话只录一次，24 次。`35 / 59 = 59.3%`。
