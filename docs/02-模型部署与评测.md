# 本地大模型部署与效果评测

> 版本：v1.0（2026-10-19）
> 目的：把拆解 Agent 从"规则桩"切换为真正的本地大模型，并给出可量化的效果证据。
> 结论先行：**qwen3:8b 全量运行在 RTX 4060 上，热态 42.3 tok/s，拆解准确率 100%（12 条标注样本），单条端到端 1.44s，全程零外网调用。**

---

## 1. 硬件与环境

| 项目 | 实测配置 | 说明 |
|------|---------|------|
| CPU | AMD Ryzen 9 7945HX（16 核 32 线程） | 纯 CPU 兜底时约 8 tok/s |
| 内存 | 16 GB DDR5（可用约 6.4 GB） | 模型走 GPU 后系统内存压力很小 |
| GPU | NVIDIA RTX 4060 Laptop，**8 GB 显存** | 计算能力 8.9（Ada），驱动 596.21 |
| 磁盘 | F 盘 SSD（剩余 360+ GB） | 模型目录放 F 盘，避免占用 C 盘 |
| 系统 | Windows 11 | Ollama 0.40.5 |

## 2. 模型选型

| 候选 | 文件大小 | 显存需求 | 结论 |
|------|---------|---------|------|
| qwen2.5:7b-instruct | 4.7 GB | ~6 GB | 可用，但生成质量弱于 Qwen3 同规模 |
| **qwen3:4b** | 4.2 GB | ~4.2 GB | 备用方案，速度快、余量大 |
| **qwen3:8b**（最终选择） | **4.87 GB**（Q4_K_M） | **~5.9 GB** | 8 GB 显存刚好装下，质量最优 |
| qwen3:14b | ~9 GB | 12 GB+ | 超显存，被迫 CPU 混合推理，不采用 |

选 **qwen3:8b** 的依据：
1. Q4_K_M 量化后权重 4.87 GB，加上 4096 上下文 KV Cache（约 576 MB）与计算缓冲，实占显存 **6.7 GB**，仍在 8 GB 以内；
2. `num_ctx` 限制为 4096——拆解任务每次只处理一段几十字的社区记录，4K 上下文绰绰有余，换来显存安全余量；
3. 备选降级路径明确：若显存不足或需要更快响应，改 `config.py` 中 `LLM_MODEL=qwen3:4b` 即可，代码无需改动。

## 3. 部署过程（含国内网络踩坑记录）

### 3.1 安装 Ollama

```bat
winget install --id Ollama.Ollama --accept-package-agreements --silent
```

> **踩坑 1**：winget 下载安装包时长期 0 字节——原因是系统代理未启用（`ProxyEnable=0`），
> winget 直连 GitHub 超时。解决：经镜像手动下载后用 `/VERYSILENT` 静默安装。
>
> **踩坑 2**：`curl` 走代理下载 GitHub 报 `schannel: server closed abruptly`，且代理对
> `github.com` 返回 502。解决：改用 GitHub 镜像 `gh-proxy.com`（实测 70 MB/s）。
>
> **注意**：`registry.ollama.ai`（模型仓库）本身可直连，只有 `github.com` 被挡，所以
> `ollama pull` 不受影响。

```bat
:: 手动安装（若 winget 失败）
curl -L -o OllamaSetup.exe "https://gh-proxy.com/https://github.com/ollama/ollama/releases/latest/download/OllamaSetup.exe"
OllamaSetup.exe /VERYSILENT /NORESTART /SUPPRESSMSGBOXES
```

### 3.2 模型目录重定向到 F 盘

必须在 Ollama **首次启动前**设置，否则模型会下载到 `C:\Users\<用户>\.ollama\models`：

```powershell
[System.Environment]::SetEnvironmentVariable('OLLAMA_MODELS','F:\ollama-models','User')
```

### 3.3 拉取模型

```bat
ollama pull qwen3:8b      :: 5.2 GB，实测约 3 分 46 秒
```

### 3.4 与系统的对接

系统的 `app/llm/client.py` 是唯一的大模型出入口，切换模型只改配置：

```python
LLM_MODEL = os.environ.get("LLM_MODEL", "qwen3:8b")
LLM_THINK = os.environ.get("LLM_THINK", "0") == "1"   # Qwen3 思考链默认关闭
LLM_NUM_CTX = int(os.environ.get("LLM_NUM_CTX", "4096"))
LLM_TEMPERATURE = float(os.environ.get("LLM_TEMPERATURE", "0.2"))
```

三个关键参数的作用：

| 参数 | 取值 | 原因 |
|------|------|------|
| `think` | `false` | Qwen3 默认先输出大段推理链，对结构化抽取纯属浪费（单条会从 1.5s 涨到 15s+），且污染 JSON |
| `num_ctx` | 4096 | 控制 KV Cache 显存占用，保证 8 GB 显存装得下 |
| `temperature` | 0.2 | 抽取任务需要确定性，低温度减少格式漂移 |

## 4. 实测性能

| 指标 | 实测值 | 说明 |
|------|--------|------|
| 冷启动加载 | 32.4 s | 含 CUDA kernel 首次编译/调优，只发生一次 |
| 热态生成速度 | **42.3 tok/s** | GPU 利用率 98%，SM 1890 MHz，55 ℃，38.7 W |
| 显存占用 | 6.7 GB / 8.0 GB | 模型 5.6 GB + KV Cache + 计算缓冲 |
| 单条拆解端到端 | **1.44 s**（均值，12 条） | 含 HTTP、prompt 编码、生成、解析 |
| 纯 CPU 对照 | 8.2 tok/s | 约为 GPU 的 1/5，验证 GPU 加速有效 |

> **踩坑 3**：首次启动时 Ollama 报 `library=cpu total_vram="0 B"`，完全没识别到显卡。
> 原因是 GPU 探测子进程异常退出（`exit=1`）。彻底结束所有 `ollama` 进程后重启即恢复，
> 日志显示 `inference compute ... library=CUDA total="8.0 GiB"`。
> **运维建议**：重启模型服务前先用 `taskkill /IM ollama.exe /F` 清理残留进程，否则会
> 出现端口占用或探测失败。

## 5. 结构化输出：从 83% 到 100% 的关键改动

### 5.1 问题现象

最初使用 Ollama 的 `format: "json"`（只保证是合法 JSON），出现两类错误：

1. 模型把多条事项**合并成一个对象**输出（"垃圾桶满了，另外健身器材也坏了" → 只返回 1 项）；
2. 顶层本该是数组，模型却输出单个对象，导致解析后丢失事项。

### 5.2 解决方案：JSON Schema 约束解码

利用 Ollama 的结构化输出能力，把 schema 直接传给 `format` 字段，解码时按语法强制约束：

```python
SCHEMA = {
    "type": "array",
    "items": {
        "type": "object",
        "properties": {
            "type": {"type": "string", "enum": ["报修", "人口变动", "走访", "调解", "咨询", "其他"]},
            "subject": {"type": "string"},
            "fields": {"type": "object"},
            "target_lines": {"type": "array",
                             "items": {"type": "string",
                                       "enum": ["物业", "综治", "民政", "卫健", "街道"]}},
        },
        "required": ["type", "subject", "fields", "target_lines"],
    },
}
```

效果：
- 顶层必为数组，**不可能**再输出单对象；
- `type` 和 `target_lines` 只能取枚举值，非法值在解码阶段就被排除，下游 Agent 的决策输入天然合法；
- 不再需要"解析失败 → 降级到规则桩"的兜底（保留作为模型不可用时的保护）。

### 5.3 预分句校验（第二道保险）

对含并列词（另外/还有/顺便/同时/此外/以及/加上）的文本先粗切子句计数，
若模型输出项数少于子句数，则带上"这段话包含 N 件事，必须输出 N 项"的提示重试一次。
实测只在真正漏拆时触发，平均耗时从 1.30s 增至 1.44s，代价可接受。

## 6. 效果评测

评测脚本：`scripts/eval_parser.py`，标注集 12 条（`CASES`），覆盖单事项、多事项、
跨业务线、并列句、群租消防等边界场景。

> **注意**：本章 6.2 的数据是**首轮试点（12 条易样本）**，用于验证"Schema 约束"这一改动是否有效。
> 正式评测已扩充到 **43 条（含 9 条难例）**并做了消融实验，权威数据见
> **`docs/03-评测与消融实验.md`**：数量准确率 97.7%、类型 F1 99.0%、去向 100%。

```bat
python scripts/eval_parser.py --verbose     :: 逐条明细
python scripts/eval_parser.py               :: 汇总报告
```

### 6.1 指标定义

| 指标 | 定义 |
|------|------|
| 业务项数量准确率 | 预测项数 == 标注项数 的样本占比 |
| 业务类型 F1 | 按类型多重集合计算的 micro-F1 |
| 业务线去向准确率 | 标注的业务线被全部命中的比例（召回口径，多送一条线不算错） |

### 6.2 结果对比

| 方案 | 数量准确率 | 类型 F1 | 去向准确率 | 平均耗时 |
|------|-----------|---------|-----------|---------|
| 规则桩（关键词） | — | 低（仅关键词覆盖） | 粗粒度 | < 5 ms |
| qwen3:8b + `format:"json"` | 83.3% | 92.3% | 78.6% | 1.30 s |
| **qwen3:8b + JSON Schema 约束** | **100%** | **100%** | **100%** | **1.44 s** |

### 6.3 典型样例

输入：`2栋2单元202室新租户李某电话13800001234，另外7栋电梯异响要检修，顺便说楼道灯也不亮了`

输出（3 项，2 张工单，1 条台账）：

| 业务项 | 类型 | 去向 | 下游动作 |
|--------|------|------|---------|
| 2栋2单元202室新租户李某登记 | 人口变动 | 综治 | 写入综治台账（命中历史档案，标记复用） |
| 7栋电梯异响需检修 | 报修 | 物业 | 生成工单 W20261019-111648-10 |
| 7栋楼道灯不亮 | 报修 | 物业 | 生成工单 W20261019-111648-11 |

同时手机号被脱敏为 `138****1234`，全程 4.5 秒，审计日志记录 Agent 调用但**外网调用 0 次**。

> 说明：12 条样本上的 100% 说明 prompt 与约束解码已覆盖这些场景，但也提示样本难度偏低。
> **该判断已被验证**：扩充到 43 条（含口语指代、同类多件、跨线组合等难例）后，
> 数量准确率回落到 97.7%、类型 F1 99.0%，详见 `docs/03-评测与消融实验.md`。

## 7. 运维与故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| `bind: Only one usage of each socket address` | 旧 `ollama` 进程占用 11434 | `taskkill /IM ollama.exe /F` 后重启 |
| 推理速度突然降到 2~8 tok/s | GPU 未识别，走 CPU | 看日志 `inference compute ... library=cpu`，清进程重启 |
| 模型下载到 C 盘 | `OLLAMA_MODELS` 未生效 | 启动前设置环境变量，或删除 C 盘 `.ollama\models` 后重拉 |
| 输出带 `思考中...` 或 JSON 解析失败 | 未关闭 think | 确认请求体 `"think": false` |
| `ollama pull` 卡住 | 仓库直连抖动 | 重试；必要时配置 `HTTPS_PROXY` 后重启 serve |

### 启动方式

| 脚本 | 作用 |
|------|------|
| `scripts/start_ollama.bat` | 只启动模型服务（模型目录固定 F 盘），窗口关闭即停止 |
| `scripts/start_app.bat` | 一键启动模型 + Flask + 打开浏览器 |

## 8. 对论文的贡献点

1. **完整的本地化部署证据链**：从硬件配置、模型选型理由、显存测算到实测吞吐与占用，可复现；
2. **结构化输出约束解码**：把"LLM 输出不稳定"这个工程难题转化为可量化的改进（83.3% → 100%），
   有对照组、有指标、有耗时代价分析；
3. **双路径降级设计**：模型不可用时自动回落规则桩，保证业务不中断——符合政务系统"可用性优先"的要求；
4. **保密性可验证**：模型、推理、数据全部在本机，审计日志可证明外网调用次数为 0。
