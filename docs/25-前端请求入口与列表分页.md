# 25 前端请求入口收口 + 公告列表分页（2026-10-23）

承接 `docs/24-整体审查.md` §3 里"看到但没改"的前两项：

| 审查结论 | 本轮 |
|---|---|
| 11 个页面**一个 `catch` 都没有**，接口抖动时静默卡在"加载中" | 收口到 `window.api()` + 顶部提示条 |
| 公告列表 `limit(200)` 无分页，第 201 条静默消失 | 加分页（`page`/`size`）+ 页脚"共 N 条" |

## 1. 为什么必须收口，而不是"每页各加一个 catch"

页面里原来有 **40 处** 各自写 `await (await fetch(u)).json()`。这个写法有三种失败形态，
而且**没有一种会在界面上说出来**：

| 失败 | 代码层表现 | 用户看到 |
|---|---|---|
| 断网 / 服务没起 | `fetch` reject（`TypeError`） | 表格停在"加载中…" |
| 网关 502/504 回 HTML | `r.json()` 抛 `SyntaxError: Unexpected token <` | 同上，控制台一行红字 |
| 隧道抖动、请求挂住 | 没有超时，永远 pending | 按钮一直"提交中…"，用户只能刷新 |

三个坑都指向同一件事：**失败与"还没加载完"在界面上长得一模一样**。
逐个页面加 catch 只是把同一个判断抄 11 遍，第 12 个页面还会忘。
所以收口到一个入口。

### 收口后的契约（关键：调用点不用改写业务逻辑）

```js
const j = await api('/api/tasks', opts);   // j 就是 {code, msg, data}
if (j.code !== 0) { ... }                  // 与原来完全一致
```

- 只有**通道层**失败（连不上 / 超时 / 回的不是 JSON）才抛异常，并且**先弹提示条再抛**——
  调用者接不接这个异常，用户都能看见发生了什么；
- 业务失败（`code != 0`）照旧返回给调用者，由它决定 `alert` 还是写进表格。
  `api()` 不替业务层做决定，否则"权限不足"和"网络断了"会被混成同一种提示。

`401/403` 仍由 `base.html` 里已存在的 fetch 拦截层处理（跳登录 / 弹无权限），
不会走到 `api()`；因此这两类不会重复弹窗。

### 提示条的设计取舍

| 决定 | 原因 |
|---|---|
| `position:fixed` 挂在 `body` 上 | `.content` 是 12 栏 grid，插一个非卡片元素会占掉一列，把所有卡片挤下去 |
| `z-index:90` | 必须高于手机抽屉（60）和遮罩（55），否则窄屏上提示被抽屉盖住 = 没提示 |
| 默认 `translateY(-160%)` 移出屏幕 | 不用 `display:none`：保留过渡动画，且不参与布局计算 |
| 成功一次就自动收起 | 恢复后还要用户手动关提示，等于把"修好了"藏起来 |
| 失败只更新文字，不叠加 | 轮询/多次点击时不该堆一屏提示条 |

## 2. 迁移过程（40 处，13 个文件）

只认三种确定形态，其余一律不碰——宁可不改，也不凭正则猜一对括号：

| 形态 | 改法 |
|---|---|
| `(await fetch(X)).json()` | `await api(X)` |
| `fetch(X).then(r => r.json())` | `api(X)` |
| `const res = await fetch(X); const j = await res.json();` | `const j = await api(X);` |

`base.html`（包装层本身）和 `pending.html`（必须判 `r.status === 401` 才能拦住未登录）
留在白名单里，由 `smoke_frontend.py` 显式断言"除这两个文件外没有裸 `fetch`"。

### 三个踩到的坑

1. **正则把 `const j` 吃掉了**：第一版按"C 形态"改写时保留了第一条语句的变量名，
   产出 `const res = api(...)`，而 `j` 从此 undefined —— 页面上是"什么都没渲染"，
   没有任何报错指向这里。改法是取**第二条**语句的声明头。
   这类错误只有"渲染页面 + 让 JS 引擎过一遍"才能发现，`grep` 看不出来。
2. **`.then(r => r.json()).catch(...)` 被切断**：`admin_user.html` 的 `post()` 是
   `await r.json().catch(() => ({code:1, msg:'返回格式异常'}))`，正则把 `.json()` 后面的
   `.catch` 留在原地，产出 `});.catch(...)`——**语法错误**。
   顺手把这段重写成"`api()` 只管通道失败，`code != 0` 翻译成异常"，
   两种失败各有各的出口，也不再需要 `r.ok`。
3. **行尾符**：仓库里 CRLF/LF 混杂（`admin_users.html` 等 8 个是 CRLF），
   Python 覆写后统一成 LF。功能无影响，但 `diff` 会整个文件都算改动，
   评审时要先 `tr -d '\r'` 再比。

## 3. 顺带修掉：4 个页面偷偷覆盖了全局 `esc`

`base.html` 提供的 `esc()` 转义 `& < > " '` 五个字符。但 `kb.html`、`orders.html`、
`tasks.html`、`notices.html` 各自又写了一个同名函数，函数声明提升会**覆盖**全局那份：

| 页面 | 旧版本转义范围 | 后果 |
|---|---|---|
| `kb.html` | `& < >` | 属性里的单双引号可打断标签 |
| `tasks.html` / `orders.html` | `& < > "` | 单引号可打断用 `'` 包裹的属性 |
| `notices.html` | `& < >` | 同上 |

所以"整站 46 处 innerHTML 都过 esc"这句话，在这 4 个页面上实际是**弱转义**。
现在四份本地定义全部删除，统一用全局那份；`smoke_frontend.py` 断言
"除 base.html 外没有任何文件再定义 `esc`"。

## 4. 公告列表分页

### 原来的问题

```python
rows = (q.order_by(...).limit(200).all())      # 第 201 条起静默消失
counts = {s: base.filter_by(status=s).count() ...}   # 卡片仍是全量
```

演示库只有 4 条公告，演示时看不出来；真实社区一年几百条上传后，
"已发布 260"配一张 200 条的列表，用户只会以为系统丢了数据。

### 现在的语义（与 `/api/ledgers`、`/api/orders` 同名同义）

| 字段 | 含义 |
|---|---|
| `counts.matched` | **当前筛选命中数**（列表指向的那一份） |
| `counts.published/pending/offline/todo/pinned` | 家底，不随筛选变 |
| `counts.page / size / pages / shown / truncated` | 分页状态 |

- **越界夹取**：`page=99` 而只有 3 页时返回第 3 页的数据并回写 `page=3`，
  而不是给一张空表配"99 / 3"；
- **非法参数回默认**：`size=0` / `size=-1` / `size=abc` 一律回 50，
  不能夹成 1（那会变成"筛出来只有一条"）；
- **上限 200**：`size=9999` 被夹到 200，防止一次拉全表。

### 顺手修掉一个 N+1

`_row()` 里原本是：

```python
p = (progress or {}).get(n.id)
if p is None and (n.kind or "superior") == "superior":
    p = _local_progress([n.id]).get(n.id)     # 每条都补查一次
```

批量渲染时 `progress` 里**没有这个 key** 表示"它没有落地件"（0 条），
不是"没查过"。结果每一条没有落地件的公告都要再发一次查询——
一页 200 条就是 200 次。改为只判 `progress is None`（单条渲染路径），
批量路径不再补查。

### 前端

- 每页 20 条，页码进网址（`?page=2`），从详情返回还在原页；
- 换筛选一律回第 1 页（否则停在"待签收第 3 页"，切到"已发布"就是一页空表）；
- 用 `replaceState` 不 `pushState`：翻页不该在浏览历史里堆一长串；
- 页脚"共 N 条（第 X 页，本页 M 条）"，与卡片同源；
- 列表为空时区分两种情况："没有符合条件的公告，换个筛选试试" vs "还没有公告，去导入"。

## 6. 没做的，以及为什么

| 项 | 现状 | 理由 |
|---|---|---|
| `api()` 自动重试 | 只给"重试"按钮，不自动重放 | 写操作自动重试会重复提交（办结、投递），宁可让人手动点一次 |
| `pending.html` 仍用裸 `fetch` | 保留 | 它要在解析前判 `r.status === 401` 才能拦住未登录/停用，`api()` 把它归一化掉了 |
| 业务失败统一弹 toast | 仍是各页 `alert` | 改弹窗形态要动 20 多处交互，风险大于收益；本轮只保证"看得见" |
| 台账/工单页也用 `.pgbar` | 仍是行内样式 | 两页分页已工作正常，统一样式属纯外观整理，留待有余力时做 |
| `size` 可由网址指定 | 否（固定 20） | 少一个可被构造的参数；需要时改常量即可 |
