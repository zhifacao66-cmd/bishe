## 二、题目简介（约 450 字，可直接粘贴）

基层社区工作者长期承担"一次数据、多头填报"的重复劳动：同一户居民信息要在综治、民政、卫健、物业等多个系统各录一遍，台账口径不一、留痕压力大；社区与街道、物业之间依靠微信群沟通，事项易丢、责任难追溯。同时，居民身份证号、健康状况、门牌住址等敏感信息受保密约束，不允许上传公有云大模型，通用智能助手在基层难以落地。

本课题设计并实现一套面向社区"极简减负"的多智能体（Multi-Agent）系统，以首录入口（FDE, First Data Entry）为核心：社区工作者用一段口语化的自然语言描述录入一次工作事项，系统自动完成敏感信息识别与脱敏、业务项拆解、按业务线自动派单、台账自动填报、工单闭环跟踪、报表汇总、超时督办与全程审计留痕，实现"一次录入、多方复用"。

技术路线：以本地部署的开源大模型（Ollama + Qwen3-8B）为推理底座，数据不出内网；采用 Orchestrator 调度与单职责 Agent 协作的架构，以 JSON Schema 约束解码保证结构化输出的稳定性；引入 RAG 检索增强对接社区政策与业务规范；通过角色权限控制与字段级脱敏审计保障合规。

实验结果表明：43 条标注语料上业务项拆解数量准确率 97.7%、类型 F1 99.0%；24 条端到端语料重复 3 次评测，漏派单率 0%、敏感信息识别召回率 100%、库内明文 0 处，单次受理 P50 2.14 秒，人工录入次数由 59 次降至 24 次（−59.3%）。课题同时完成并发压测与长稳测试，给出同步改异步、单卡串行推理吞吐上限等工程结论，可为同类"本地大模型 + 智能体"的政务与社区应用提供可复用的设计与评测范式。

## 三、基本要求（约 380 字，可直接粘贴）

一、能力要求
1. 掌握 Python 编程与 Web 开发（Flask 或同类框架），能独立完成接口设计、前后端联调与部署；
2. 了解大语言模型基本原理与提示工程，具备本地模型部署与推理调优能力（量化模型、显存约束、并发控制）；
3. 理解多智能体协作、RAG 检索增强、结构化输出（约束解码）等方法的实现思路；
4. 掌握数据库设计与 SQL，理解事务边界、索引、并发控制与锁机制；
5. 具备规范的工程习惯：版本管理、日志与审计、可复现的测试脚本与实验记录。

二、工作量与成果要求
1. 完成需求分析与总体设计文档，给出系统架构图、业务时序图与数据模型；
2. 实现首录、保密审查、任务拆解、派单、台账、报表、督办、审计等核心模块并打通全链路；
3. 构建不少于 40 条的标注评测集，完成模型效果评测与消融实验，给出量化指标；
4. 完成三方角色权限控制、并发压测与长时间稳定性测试，输出测试报告；
5. 撰写毕业设计论文与部署使用说明，系统须可演示、可复现。

三、纪律要求
涉及居民个人信息的实验数据一律脱敏，不得上传公有云；引用他人成果须规范标注；按学院进度节点提交中期检查与答辩材料。
